# 2026-09-22 实现与验收记录

## 本次实现

- 登录 Demo 的身份选择双栏迁入主登录入口，接现有 AuthSession、SwiftData 会话与真实学生账号登录。访客/教职工暂不开放，没有绕过登录或模拟成功。
- 候选词按文本、筛选模式、展开状态触发 350ms debounce。继续输入会收起旧正式结果；任务使用始终存在的 VStack 容器，不再把任务挂在初始为空的 Group 上。smart 建议为空时回退 results；提供无结果/错误提示。
- 正式结果使用提交时的关键词，数据到达后逐条弹簧缩放、位移、轻模糊展开。减少动态效果时简化为淡入。未复刻 watchOS 系统私有动画。
- 课表默认今天；左侧日期轨道支持点选、长按拖动、越界翻周（节流），上部周预览与下部当天时间线同步。今天着强调色，选中日期显示背景。单节日历编辑器、当天/本周 ICS 导出仍保留。
- 首页、详情、地图共享课表数据。地图立即响应数据变化；退出/切账号使旧请求失效，避免旧课程写回新会话。
- `Views/Components/WaveComponents.swift` 是独立可复用组件库：WaveProgressView 与 WaveSlider；不依赖认证。Xcode 工程使用 Components 同步目录。

## 重点手动验收

已执行：iOS Debug 模拟器通用目标构建通过（arm64/x86_64）；Web 生产构建与 ESLint 通过，浏览器检查桌面/窄屏深色布局。iOS 仍有原有工具包废弃 API 与并发警告，未作无关改动。以下设备交互清单尚未逐条实际跑完，不将编译通过等同端到端验收。

1. 无会话启动：身份选择 → 学生登录；其他身份只展示说明；失败不能进入主页。
2. 搜索连续输入：350ms 内不请求最终候选；停下后出现加载/候选/空或错误提示。
3. 提交一次搜索后再编辑；换筛选模式；清空；收起再展开；检查旧候选不回写。
4. 结果收到后逐条展开；系统减少动态效果下没有放大/模糊。
5. 课表打开是今天；无课显示无课，不偷偷跳到历史演示日期；日期点选/长按滑动/越界翻周。
6. 日期轨道和周卡片联动；一节课程添加日历、当天和整周 ICS 导出。
7. 首页、地图、详情一致；课表加载时退出登录再换账号，不出现上个账号的课程。
8. 波浪控件端点、VoiceOver、深浅色及减少动态效果。

构建验证不能替代真实账号、定位权限和日历授权的设备联调。演示数据库课表与促销有历史时间范围；空课表/过期优惠不一定是 UI 故障。当前 ICS 解析仍不是 RFC 5545 完整实现（如 EXDATE、复杂 RRULE 与 TZID 仍需专项测试）。

## 比赛方案建议（未实现）

推荐主线：**校园时间预算助手**，而不是再做一个聊天入口。

- 输入“下节课前想吃饭/打印/取快递”，把地点、课程开始时间、步行时间、排队估计与安全缓冲组合起来，筛掉不可完成的方案。
- StatusBar 显示“现在出发 / 可顺路完成 / 不建议绕路”，点击展开计算依据、数据更新时间和备选方案；没有路线数据时明确未知。
- 核心计算用确定性规则；AI 只把自然语言变成结构化意图、解释推荐理由。学校维护楼宇与教室的坐标映射，避免地图文本搜索误认校外同名建筑。
- 无障碍路线、雨天遮雨路线可作为差异化加分项，但需校方验证路线数据，不宣称未核实道路安全。
- 演示用“课程临时换楼 → 原路线来不及 → 自动重排取餐/打印 → 展示解释”这条完整故事，比功能数量更有说服力。

当前最大产品痛点：可靠数据闭环尚未打通。学校端仍有 mock 数据和模拟成功，客户端有历史演示数据，楼宇定位缺标准化映射。先完成学校发布 → 学生刷新 → 地图时间提醒这一条可信闭环。

当前上线风险：APIConfig 仍是 HTTP 基础地址，旧文档中的鉴权/密钥整改需逐项复核；这些不应因为 UI 更完善而被误认为已经解决。
